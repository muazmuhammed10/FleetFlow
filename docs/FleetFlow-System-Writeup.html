Section 1

System Introduction & Overview

A full-stack, production-ready vehicle rental and fleet management platform built with modern web technologies.

FleetFlow is a secure, full-stack web application designed to manage every aspect of a vehicle rental business. It covers the complete operational lifecycle — from browsing and booking a vehicle online, through payment, pickup, active rental, return inspection, and final invoicing — all within a single unified platform.

The system is built for real-world use, with a focus on security, data integrity, and role-appropriate access. It supports four distinct user roles — Administrator, Fleet Manager, Rental Agent, and Customer — each with a tailored interface and strictly enforced permissions on the backend.

What FleetFlow Solves

Traditional vehicle rental businesses often rely on spreadsheets, paper contracts, and disconnected tools. FleetFlow replaces all of that with:

  • A customer-facing booking portal where clients browse vehicles, check availability, submit bookings, and pay online
  • A staff management console where agents approve bookings, record pickups and returns, and manage vehicle inspections
  • A fleet operations dashboard where managers track vehicle utilisation, schedule maintenance, manage drivers, and export reports
  • A secure audit trail that records every action performed in the system for compliance and accountability

Key Capabilities

🚗 Fleet Management
Add, edit, and track every vehicle — availability, compliance dates, mileage, and service history.
📅 Booking System
Real-time availability checking with concurrency-safe double-booking prevention using serializable database transactions.
💳 Payment Flow
Structured simulated payment with security deposit, collateral tracking, and full transaction history.
🔧 Maintenance
Schedule and track all service records, assign technicians, and automatically flag vehicles as unavailable during maintenance.
👥 Driver Management
Maintain driver profiles, track licence expiry, manage availability, and assign drivers to bookings.
📊 Reports & Exports
Generate booking and payment reports. Export CSV files with formula injection protection for safe analysis.
🛡️ Security & Audit
Argon2id password hashing, JWT tokens, rate limiting, and a complete audit log of all system events.
📋 Contracts
Generate and manage rental contracts tied to confirmed bookings, with full term documentation.

Section 4

Authentication — Login & Registration

Secure access control with Argon2id hashing, JWT tokens, and rate limiting.

FleetFlow uses a modern JWT-based authentication system. When a user logs in, they receive a short-lived access token (15 minutes) and a long-lived refresh token (7 days). The access token is automatically refreshed in the background so users are never interrupted mid-session. Passwords are hashed using Argon2id — the strongest password hashing algorithm available — with 64 MB memory cost and 3 iterations.

🔒 Security note: Public registration always creates a Customer account. It is not possible to self-register as an Administrator or Fleet Manager. Staff accounts are created by administrators only.

Section 5

User Roles & Permissions

FleetFlow has four distinct roles, each with a tailored interface and strictly enforced backend permissions.

Role-based access control (RBAC) is enforced on every API endpoint on the server. The frontend interface simply reflects what each user is allowed to do — hiding a button does not grant access. If a user attempts to call a restricted API endpoint directly, the server rejects the request with a 403 Forbidden response.

🔴 Administrator Highest Access

The Administrator has full access to every module in the system. They can manage all users, vehicles, bookings, payments, contracts, maintenance, drivers, and reports. They are the only role with access to the Audit Log, which records every action performed in the system. Administrators can change user roles, suspend accounts, and create staff members.

Sidebar modules: Dashboard, Vehicles, Bookings, Contracts, Customers, Payments, Maintenance, Drivers, Reports, Notifications, Audit Log

🟡 Fleet Manager Operations

The Fleet Manager oversees the vehicle fleet and operational side of the business. They can add and edit vehicles, schedule maintenance, manage drivers, view revenue charts, and export reports. They can also approve bookings and manage contracts, but they cannot access the Audit Log or change user roles.

Sidebar modules: Dashboard, Vehicles, Bookings, Contracts, Customers, Payments, Maintenance, Drivers, Reports, Notifications

🟢 Rental Agent Front Desk

The Rental Agent handles the day-to-day customer interactions. They can approve or reject bookings, record vehicle pickups and returns, verify customers, create contracts, record payments manually, and manage maintenance requests. They cannot modify vehicle pricing, access financial reports, or view the audit log.

Sidebar modules: Dashboard, Vehicles, Bookings, Contracts, Customers, Payments, Maintenance, Drivers, Notifications

🔵 Customer Self-Service

The Customer can browse available vehicles, submit booking requests, make payments for approved bookings, and view their own rental history. They cannot access any other customer's data, modify prices, or access any staff module. All data access is strictly limited to records they own.

Sidebar modules: Dashboard, Vehicles, Bookings, Payments, Notifications

Agent Responsibilities

A Rental Agent's typical daily workflow in FleetFlow:

1
Review Pending Bookings
Open the Bookings page and filter by PENDING status. Review each request for valid dates and vehicle availability.
2
Approve or Reject
Click the booking to open the detail page. Click Approve (notifies customer, who can then pay) or Reject (with an optional reason shown to the customer).
3
Record Pickup Inspection
When the customer arrives, record the pre-rental inspection — current mileage, fuel level, any existing damage — and confirm pickup. Booking moves to ACTIVE.
4
Record Return Inspection
When the vehicle is returned, record the post-rental inspection. The system calculates late-return fees automatically. Booking moves to COMPLETED.
5
Verify Customers
Check driving licence details on the customer profile and mark the customer as verified once their identity is confirmed.

Section 10

Booking & Payment Lifecycle

The complete end-to-end journey from booking request to rental completion.

FleetFlow models the full rental workflow as a state machine. A booking passes through defined statuses, with each transition triggering notifications, payment requirements, and vehicle status updates.

1
Customer Submits Booking → PENDING
Customer selects vehicle, dates, and location. The server calculates all pricing (daily rate × days + tax + security deposit) and checks availability using a serializable database transaction to prevent double-booking. Customer receives a notification confirming submission.
2
Staff Approves Booking → APPROVED
An agent or administrator reviews the booking and approves it. The customer receives a notification and a blue "Payment Required" banner appears on their booking detail page.
3
Customer Pays → CONFIRMED
Customer opens the payment page, selects a payment method (Card, Cash, or Bank Transfer), provides a security deposit guarantee (Credit Card Hold, ID Copy, or Cash Deposit), agrees to terms, and submits. All payments are clearly marked as SIMULATED. The booking advances to CONFIRMED.
4
Staff Records Pickup → ACTIVE
On the pickup date, a rental agent records the pre-rental inspection (mileage, fuel level, existing damage). The vehicle status changes to RENTED and the booking becomes ACTIVE.
5
Staff Records Return → COMPLETED
When the vehicle is returned, the agent records the post-rental inspection. The system automatically calculates any late return fees (grace period of 2 hours, then 1.5× daily rate per late day). The vehicle status returns to AVAILABLE and the booking is COMPLETED.
6
Security Deposit Released
Once the vehicle is confirmed returned in good condition, the security deposit is released back to the customer. Any damage costs or late fees are charged from the deposit before release.
💡 Pricing transparency: All financial totals are calculated on the server. Customers cannot manipulate prices by modifying API requests — any price submitted by the client is ignored and recalculated server-side.

Security Features

Security is built into every layer of FleetFlow, not added as an afterthought.

Security ControlImplementation
Password StorageArgon2id with 64 MB memory cost, 3 time iterations, 4 parallel threads. Industry's strongest algorithm.
AuthenticationJWT access tokens (15-minute expiry) + refresh tokens (7-day expiry). Refresh tokens are stored in the database and can be revoked on logout or password change.
AuthorizationRole-based access control enforced on every API endpoint. Frontend UI changes reflect permissions but the backend independently verifies every request.
IDOR ProtectionCustomers can only access their own bookings, payments, and notifications. Any attempt to access another user's data returns 403 Forbidden.
Rate LimitingAuth endpoints: 10 attempts per 15 minutes. Password reset: 5 per hour. General API: 100 per 15 minutes.
SQL InjectionAll database access through Prisma ORM with parameterized queries. Raw SQL is never used.
Security HeadersHelmet.js sets: Content-Security-Policy, X-Frame-Options, X-Content-Type-Options, Referrer-Policy, and more.
CORSRestricted to the configured frontend origin only. No wildcard CORS.
Input ValidationAll request bodies validated with Zod schemas before processing. Invalid inputs return structured error messages.
CSV InjectionAll CSV export fields are sanitised. Values starting with =, +, -, @, tab, or carriage return are escaped to prevent formula injection in spreadsheet applications.
Concurrency SafetyBooking creation uses PostgreSQL serializable isolation level to prevent double-booking under concurrent requests.
Audit LoggingAll logins, logouts, password changes, booking approvals, payments, and admin actions are logged with timestamp, actor, IP address, and resource reference.
Secret ManagementAll secrets (JWT keys, database credentials) are in .env files which are gitignored. No secrets are committed to the repository.
Production SafetyStack traces are suppressed in production responses. Error messages are generic to prevent information leakage.
Payment SecurityOnly the last 4 digits of a card are ever stored as a display reference. No card numbers, CVVs, or full payment credentials are stored anywhere.
